# Contributing

Thanks for wanting to help out. Markdown Viewer is a small project run by one person, so the process is kept simple and a bit strict.

## Issues

Bug reports and feature ideas are welcome. Before opening one:

- Search existing issues first
- For bugs, include your OS and version, the app version, what you did, what you expected and what happened
- A small markdown file that shows the problem helps a lot

## Pull requests

Pull requests are limited to collaborators. If you'd like to work on something:

1. Open an issue describing the change
2. Wait for it to be discussed and accepted
3. If it makes sense for you to do it, you'll be invited as a collaborator for that change

Pull requests that skip this, or that look like they were generated and sent without a real person reviewing them, get closed without review.

## AI tools

Using AI tools while you work is fine. Sending their output without understanding it isn't. If you open a pull request you're expected to:

- Have read and understood every line you changed
- Be able to explain why the change is needed and how it works
- Have built and run the app yourself on at least one OS

## Code style

- Match the code around your change
- Keep changes small and focused on one thing
- Avoid comments unless something really isn't obvious
- No new dependencies without talking about it in the issue first
